# 已知陷阱清单

> 从 Neox 带走的**知识**。代码不带，坑不能重踩。
> 每条格式：现象 → 真因 → 在 Neox OS 里的对策。
> 这份清单是活的：新工程每踩一个结构性坑就往这里加一条。

---

## A. 结构性成因（这些坑的根都一样）

### A1 · 双真相源
**现象**：怎么调都对不齐（布局差几像素、状态一会儿对一会儿错、数字两处不一样）。
**真因**：同一个事实被两个地方各自计算/存储。Neox 里出现过至少四次（feed 双居中、顶栏两处各写各的数、服务面板四份状态、运行态多状态员）。
**对策**：Neox OS 里**事件日志是唯一真相源**。任何派生状态必须可从日志重放得出；不可重放的状态一律不许持久化。`findPidOfDecision()` 刻意从日志里找而不是维护一张映射表，就是这条。

### A2 · 缺省不安全
**现象**：模型少传一个参数，文件被整个覆盖（append 漏 mode → 缺省 overwrite → 毁掉前两段）。
**真因**：把"最常用"当成"缺省"，而不是把"最不可逆"当成"必须显式"。
**对策**：ABI 里任何有破坏性的操作**没有缺省值**。歧义即拒绝，返回明确错误，不猜。

### A3 · 硬编码白名单
**现象**：同一个文件开出 4 个 tab；新类型加进来行为就不对。
**真因**：分支里写死了 kind 白名单，漏掉的走默认分支。
**对策**：用**全量映射表**（`Record<Kind, 策略>`），TS 的 exhaustive check 保证加新类型时编译失败。`capabilities.ts` 的 `scopeMatches` 用 switch 全覆盖 axis 就是这条。

### A4 · 边界只有被强制时才存在
**现象**：`exports` 收窄只在打包版炸；内部"约定"的分层随手就被穿透。
**真因**：同 repo、同版本号、同发布节奏的边界是假边界。
**对策**：ABI 独立包 + 边界闸（`tools/forbidden-words.mjs`）+ 应用只拿得到 `ProcessContext`，拿不到 OS 实例。

### A5 · 止血当根治
**现象**：补一处让现象消失，过两天从别处冒出来。
**对策**：只改结构性成因。修之前先问"这是 A1–A4 里的哪一个"。

## B. 执行与并发

### B1 · 流式工具参数必须按 index 归位
**现象**：模型"生成了坏 JSON"。
**真因**：并行 tool_use 的 delta **允许交错**。追加到"最后一个"会把 A 的参数接到 B 的尾巴上。
**对策**：按 index 寻址。**找不到归属宁可丢弃，不许猜**。

### B2 · 判死口径要三道闸一起改
**现象**：子进程报 "aborted / timeout"，但它其实还活着。
**真因**：改判死标准时只落了三道闸的两道（后台墙钟关了、迭代数归零了，前台墙钟还在硬砍）。
**对策**：Neox OS 里**只有 OS 判死**（预算 + abort signal 两处，且都在 `os.ts` 内）。任何第二个判死点都是 bug。

### B3 · 判死时不要扔掉已有产出
**现象**：进程被判死，上游只能原样重派，之前的工作全废。
**对策**：`proc.outcome` 事件必须落日志，失败也要带上已产出的部分。

### B4 · 墙钟 ≠ 活跃时长
**现象**：等用户回复的时间被算进超时，用户去开个会回来任务死了。
**对策**：`waiting` / `suspended` **不计入 activeMs**（已在 `os.ts::setState` 实现，并有测试锁住）。

## C. 数据与持久化

### C1 · 压缩不能 replaceAll
**现象**：压缩之后用户原话没了。
**真因**：走 replaceAll 落盘，漏回调则退回压缩前，成功则原文永久消失。
**对策**：日志**只追加**。压缩产出的是新事件，不是对旧事件的改写。

### C2 · 新表必须在 migration 幂等路径里
**现象**：本地好好的，线上启动就崩。
**对策**：任何持久化 schema 变更走同一条幂等迁移路径。

### C3 · SQLite REPLACE + CASCADE 陷阱
**现象**：更新一行，子表数据被级联删光。
**真因**：`REPLACE` = DELETE + INSERT，触发 CASCADE。
**对策**：用 `ON CONFLICT DO UPDATE`，不用 `REPLACE`。

### C4 · 落库存结构不存渲染文案
**现象**：换语言/换主题后历史记录还是旧文案。
**对策**：`PresentSpec` 描述**语义**不描述像素，渲染完全在客户端。已写进 ABI。

## D. 路径与平台

### D1 · 路径规范化会把 UNC 压没
**现象**：`\\host\share` 变成 `/host/share`，指向完全不同的地方。
**真因**：把连续斜杠压缩成一个。
**对策**：`capabilities.ts::normalize` 刻意**不压缩连续斜杠**。

### D2 · 前缀比较会误判路径
**现象**：授权 `/a` 结果 `/ab` 也过了。
**对策**：按路径段比，不按字符串前缀比。已在 `pathWithin` 实现。

### D3 · 通配符授权不连带父域
**现象**：授 `*.example.com` 结果 `example.com` 也能访问。
**对策**：刻意不覆盖父域，要就显式再授一条。已在 `hostMatches` 实现并注释。

## E. 安全

### E1 · 自报 IP 必须校验网段
**现象**：SSRF —— 控制面带着凭据去 POST 一个被投毒的地址（169.254.169.254 拿云元数据）。
**对策**：只放行 RFC1918。任何"由被管理方自报、由管理方访问"的地址都要过白名单。

### E2 · minify 不是保护
**现象**：npm 发布泄漏 51k 行可读源码。
**真因**：`keepNames` 让类名全存活，**字符串从不被压缩**（提示词明文）。
**对策**：要保护就别发；发了就当它是公开的。

### E3 · 临时约束绝不走全局通道
**现象**：想设一次性约束，结果被长驻进程继承摘不掉 / 参数看着 per-process 实则落了全局盘。
**对策**：Neox OS 里约束**只能挂在 Process 上**，随进程消亡。没有全局可变设置。

### E4 · 缺省是拒绝
**对策**：空能力集 = 什么都不能做。已在 `capabilityAllows` 实现。

## F. 呈现与交互

### F1 · 订阅补齐不许乱序或断层
**现象**：断线重连后先看到 seq=9 再看到 seq=5；或者中间少了几条。
**真因**：补齐历史期间到达的实时事件插了队。
**对策**：`EventLog.subscribe` 补齐期间把实时事件入队，补完按 seq 去重放出。已有测试锁住。

### F2 · 拒掉的输入必须对用户不可见
**现象**：用户看到自己被系统丢弃的操作还留在界面上。
**对策**：被拒的操作不进日志的 `proc.output`，只进审计面。

### F3 · 不要静默默认
**现象**：超时了系统替你选了，但你不知道。
**对策**：超时兜底也走 `decide.resolved`，`by: 'timeout'` 写进日志。已有测试锁住。

## G. 验证方法

### G1 · 真机验证要真点界面
**现象**：走 IPC 调内部方法验证通过，真实用户点了却全失败（因为 UI 上的状态跟库里的不是一回事）。
**对策**：验收必须走跟用户等价的路径。M0 的验收脚本要能"真的关掉客户端"。

### G2 · 别被基线的绿骗过
**现象**：收尾闸门全绿，但基线本来就是绿的，改动根本没被覆盖。
**对策**：新增能力必须新增**会失败的测试**，先看它红再看它绿。

### G3 · 进度要实时可见
**现象**：输出 pipe 进 tail，跑完前谁都看不到进度。
**对策**：长任务的进度走事件流，不走缓冲输出。

### G4 · 测试靶子绝不用真仓库
**对策**：任何会写文件的测试用临时目录，不用用户的真实工程。
