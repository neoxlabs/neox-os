# 接一台 Home Assistant

两半：**感知**（家里发生了什么 → OS 知道）和**控制**（OS 吆喝一声 → 家里去做）。
感知那半仓库里早就有，控制这半是 2026-09-12 补的。

## 拓扑：HA 装在家里，不装在机房

理由不是内存，是**HA 的价值在于连你家里的设备**（Zigbee 网关、灯、锁、传感器）——
机房那台够不着你家局域网。

```
        家里                                    机房
┌────────────────────────┐              ┌──────────────────┐
│ Home Assistant :8123   │              │  neox-console    │
│        ▲   ▲           │              │   (OS + bot)     │
│        │   │           │              │                  │
│ neox-sense-ha ─────────┼── 出站 ─────▶│ POST /signal     │  感知
│        │               │              │                  │
│        └───────────────┼── 出站 ─────▶│ GET  /stream     │  控制(听吆喝)
└────────────────────────┘              └──────────────────┘
```

**家里只有出站连接**：HA 一个端口都不用往公网开，路由器不用配转发，
不用 Cloudflare Tunnel，也不用把家里的网暴露给机房那台机器。

## 第一步：感知（不用写代码）

1. 家里起 HA（树莓派 / NAS / 闲置小主机都行）。
2. HA 里建一个**长期访问令牌**：头像 → 安全 → 长期访问令牌。
3. 在**同一台机器**上跑采集器：

```sh
HA_BASE_URL=http://127.0.0.1:8123 \
HA_TOKEN=<长期访问令牌> \
NEOX_SENSE_URL=https://<你的 OS 入口> \
NEOX_SENSE_TOKEN=<OS 的 observe token> \
HA_POLL_SEC=10 \
HA_EPSILON=0.05 \
  ./neox-sense-ha
```

- `HA_POLL_SEC` **就是最坏延迟**：门锁被打开最坏晚这么久才知道。
- `HA_EPSILON` 数值传感器变化多少算"变了"（0.05 = 5%）。
  **这一个数挡掉的噪音比其它所有规则加起来都多**：温度 22.0→22.1 不报，22.0→24.0 报。

跑起来之后，"门开了""锁开了""客厅有人"会进世界模型，
可以对 bot 说"有人开门就告诉我"（走 `notify_when`）。

### 为什么是轮询而不是订阅 WebSocket

HA 的 WS 能推 `state_changed`，看着更实时，但它推的是**每一次微小变化**，
我们照样要在本地过滤一遍——实时性买到的是更多噪音。而轮询+比对天然是
**电平触发**的：只在"跟上次不一样"时才报，漏一次轮询不会丢状态（下一次照样比出来），
而漏一个 WS 事件会。

在一台运行 11.3 天的 HA 上校准：**127 万次观察收敛为 97 条信号**，降噪 99.8%，
真事件一条不丢。降噪规则实现在 `go/sense/`。

## 第二步：控制（两道开关，默认都关）

```sh
# 家里这台，加一个
HA_CONTROL=1

# 机房那台，加一个
NEOX_HOME_ON=1
```

**采集是读，控制是写，不该一起默认打开。**

打开之后 bot 多一个 `home` 工具：

```
home(what="客厅灯", do="on")     # on 开 / off 关 / toggle 切换
```

### 一句吆喝怎么走

1. bot 调 `home` → console 落一条 `device.act`（`{device:"ha", act:"on", name:"客厅灯"}`）。
   **不进账本**：它是一句吆喝，不是一件发生过的事。
2. 家里的采集器从 `/stream` 收到这条。
3. 采集器拿**当下**的实体表按 `friendly_name` 匹配 →
   `客厅灯` → `light.living` → 域 `light` → 过白名单 → 调 `POST /api/services/light/turn_on`。
4. 灯真亮了，下一轮比对会投一条状态信号上来——**那条才是事实**。

所以 `home` 工具的返回只说"吆喝出去了"，不说"开好了"：
说成后者就是替一件还没发生的事作保。

### 三道闸

| 闸 | 在哪 | 挡什么 |
|---|---|---|
| 白名单 | 家里这侧 | 只放行 灯/开关/场景/脚本/窗帘/空调/风扇/媒体/加湿/扫地。**锁和安防不在里面** |
| 唯一匹配 | 家里这侧 | 家里两盏灯都叫"灯"时**什么都不做**，让他说准一点 |
| 两个开关 | 两侧各一个 | 默认关；只开感知不开控制是完全正常的用法 |

**锁不在白名单里不是忘了**：开灯错了再关掉，开锁错了是另一回事。
要放开也该是你改这张表（`sense/haact.go` 的 `actAllowed`），而不是模型某天想通了。

### 断线怎么办

- 流断了就退避重连（2s 起，翻倍到 1 分钟封顶）。
- OS 每 20 秒发一行 SSE 注释顶着——一条安静的流会被路上每一跳掐掉，
  而"断了"和"今天很安静"长得一模一样。
- **断掉期间的动作不补**：十分钟前那句"开灯"现在执行才吓人。

## 代码在哪

| 东西 | 文件 |
|---|---|
| 状态 → 信号（降采样、语义翻译） | `go/sense/ha.go` |
| 采集器主程序 | `go/cmd/neox-sense-ha/main.go` |
| 听吆喝 + 调 HA 服务 + 白名单 | `go/sense/haact.go` |
| 吆喝那条事件 | `go/abi/types.go` 的 `EvDeviceAct` |
| bot 的 `home` 工具 | `go/agent/proactive.go` 的 `HomeTool` |
| console 侧发吆喝 | `go/cmd/neox-console/history.go` 的 `homeAct` |
| 在真 HA 上重放一天做验收 | `go/cmd/neox-ha-day/main.go` |

## 验收

`neox-ha-day` 在真 HA 上重放一天的住宅活动——**它只调 HA 的服务，
一个字节都不碰采集入口**。灌合成信号会绕过采集器的全部判据，
那样量出来的是"我编的信号有多吵"，不是"这套过滤有多好"。

```sh
HA_BASE_URL=http://127.0.0.1:8123 HA_TOKEN=<令牌> DAY_SECONDS=1200 ./neox-ha-day
```
